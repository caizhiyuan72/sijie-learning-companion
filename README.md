# 思阶——防认知外包的智能学伴

## 2026-11-17 点选本题卡点求助

求助页支持“选卡点 → 帮我理解 → 继续思考”：AI在现有学习任务生成中一并整理3—5个本题具体卡点，不增加独立的拆解请求；学生单选后即可求助，也可展开补充文字或图片。最新提示集中显示，历史求助和知识卡按需展开。先思保持原有方式；手机保留题目/作答两页，电脑保留题目与作答双栏，卡点在各端均为单列。

连续求助会在每次成功提示后更新下一组卡点：同一次提示生成同时给出针对刚才回应的 `nextHelpOptions`，结合此前点选和提示继续细化；页面先展示最新提示，再展示新的“这一步还有哪里不明白？”选项，并清空上一轮选中状态。当前选项保存在学生自己的 `session.helpOptions` 中，通过 `task.helpOptionsRound` 标识轮次，不修改共享题目。已建立轮次后，旧轮ID不能再次消费提示；旧会话缺少该字段时根据最近提示提供通用后续卡点，已打开的旧版页面可用原卡点接续一次，随后切入轮次校验。三级额度仍按整题累计，提示生成失败不切换当前选项，也不消耗次数。

连续点选修正已通过164项自动测试、手机三轮与电脑两轮浏览器验收，以及原有手机布局和图片回归。线上用方程、比例题分别连续两轮纯点选验证，确认每轮卡点文案更新、选择不算理解通过；临时验收记录已按ID清理。当前版本为 `a660ab97-aeab-4f02-9d90-a426456e4aca`，更新前版本为 `f253edcd-c4d9-4b6f-aa93-02a9bdd54477`。验收记录见 `output/help-qa/dynamic-verification.json`，截图位于 `output/help-qa/dynamic-local/` 与 `dynamic-online/`。

点选仅代表学生表达困难，不算理解通过。主按钮只请求提示；“检查我的理解”提交真实解释，“我懂了，进入判别”仍标记为辅助继续。三级提示额度按整题累计，换卡点不重置；生成失败不消耗额度。三级用完后可以仅凭选中的卡点提交教师看板，保存不代表老师已收到通知。

新任务字段为 `helpOptions: [{ id, label }]`，仅求助阶段公开。`POST /api/session/:id/help` 支持 `action: "hint"`、`selectedStuckPointId` 及可选的 `text`、`imageData`；教师求助也接受该选项ID。服务端从当前题目的白名单解析标签，独立记录 `answers.helpSelections`，不把AI标签写成学生原话。旧任务、缺少有效选项或仅完成结构恢复的任务使用明确标注的通用卡点；无需迁移历史数据。

## 运行与试用

需要 Node.js 22。在本目录运行 `npm install`，按 `.env.example` 配置后运行 `npm start`，打开 http://localhost:4180 。学生可在页面填写模型密钥；页面填写的密钥仅保留在服务进程内存中，重启需重新填写。未配置模型时，识题明确停止，不伪装成已调用AI。

- 学生端：`/`，输入题目文字或上传题图，核对题面后开始。
- 教师端：`/teacher`，兼容`/teacher.html`与`/teacher/`，查看当前卡点、学生原话、已给提示和建议追问。
- 未设置 `TEACHER_TOKEN` 时，教师记录仅允许从本机地址查看；设置后本机和远程均需口令。不要将本地服务直接当作学校公开部署。
- 学习数据继续保存在 `data/runtime/`；测试使用临时目录，不覆盖已有记录。

## 2026-09-06 学习流程改进

1. 识题与学生先思分离：AI识别题面不算学生作答；先思不要求学生先写第一步想法，而是分别填写“已知/题目条件”和“求证/求解目标”。
2. 先思可以补充手写草稿，或选择“不知道题目给了什么条件 / 不知道用哪个公式或定理 / 不知道从哪里开始”。卡点单独记录，绝不伪造学生文字。
3. 求助通常通过一句自己的解释进入判别；第二部分也提供“我懂了，进入判别”按钮，直接进入判别并标记为在帮助下完成，不伪造数学解释。
4. 三级提示用完仍停留在求助，不自动放出完整解析。学生可把卡点提交教师看板，或继续解释来检查理解。保存到看板不等于老师已收到通知。
5. 新迁移题要求改变关键条件或推理方向、检验条件作用，不能只更换字母。历史任务不自动改写。
6. 教师看板将原始表达和提示放在一起，帮助教师判断在哪里介入；系统不诊断学生能力或AI依赖。

## 2026-11-11 五阶段、图片上传与知识库

学生流程为“先思 → 求助 → 判别 → 迁移 → 反思”。迁移和反思使用已有独立状态标识，旧会话无需改写；反思页可回看自己的先思、已经给过的提示和迁移反馈。

手机端把“题目”和“阶段作答”分为两页，左滑进入作答、右滑回看题目，并提供点击切换。各页保留自己的滚动位置，切换不清空输入；桌面继续并排查看。新题导入、题稿核对在题目页完成，开始学习后进入阶段作答页。

完成页面和教师摘要区分“流程完成”和学习证据。自声明理解、使用提示或达到尝试上限后的辅助继续会如实标注，不作为独立掌握；判别、迁移分别展示核验状态。任务同时记录模型内容复核状态，仅通过结构检查的任务标为需教师复核；旧记录没有核验信息时也不补造通过记录。这些标签描述本次过程，不代表长期学习效果。

题目导入和五阶段作答均保留“选择图片”入口。独立“拍照”按钮因系统相机唤起兼容性无法可靠保证而移除；请先用手机系统相机拍好，再选择图片上传。每个作答区保存一张当前图片，可替换、删除；长边不超过2048px，逐步压缩目标为2MB，最终上限8MB。图片先在浏览器去除元数据；HEIC取决于浏览器解码能力，不支持时会明确提示，保留上一张可用图。题目原图不会自动成为学生作答。先思手写图可以代替“已知”文字，求解目标仍需确认。

图片处理期间阻止提交；模型或网络失败后保留当前图文与选择。错误响应包含失败步骤、请求编号、是否可重试及耗时；上游认证、模型不可用、图片输入被拒绝等永久错误不自动重试。识题的提取、格式重试与二次核验共用45秒时限；其他主要模型操作共用90秒时限，单次请求仍受30秒限制。修正题稿后可再次核验，无需重新选图。以上时限不代表识别准确率或端到端网络耗时保证。

### 知识库存在哪里，AI怎样使用

- 本地：`data/runtime/knowledge-cards.json`（若设置`DATA_DIR`则位于相应数据目录）；云端：现有D1数据库中的`knowledge_cards`表。学习记录继续保留在原位置。
- 内容：数学知识与教学策略按条目、状态和版本保存，记录来源、年级、适用条件、常见误用、引导问题和阶段策略。首批基础卡为项目整理，按所附公开资料核对，仍标注待教师复核。
- 教师在`/teacher.html`可查看、编辑、保存草稿、发布和停用，沿用教师口令。保存草稿不替换已发布内容；发布与停用生成新版本，历史版本保留。
- AI不直接访问数据库。后端结合已确认题目、年级、当前阶段及本轮卡点选择少量条目，再附入模型输入；一次最多两张数学卡及当前阶段策略。无可靠匹配时不硬套。
- 先思不展示知识提示；求助可展示通用知识卡；判别、迁移仅在服务端使用相关依据，不在迁移作答前展示解题提示。教师摘要记录提供给模型的条目ID、版本及匹配原因；这不能证明模型一定采纳。

教师接口（均要求现有教师认证）：`GET /api/teacher/knowledge`、`POST /api/teacher/knowledge/draft`、`POST /api/teacher/knowledge/:id/publish`、`POST /api/teacher/knowledge/:id/disable`。教师新增或修改内容先保存草稿，再发布；不支持教材文件上传、向量数据库或自动认定教师审核。

首次部署时，将 `wrangler.example.jsonc` 复制为 `wrangler.jsonc`，填写自己的 Worker 名称、D1 数据库名和 ID。通过 Cloudflare Worker 的 Secrets 配置 `TEACHER_TOKEN` 和 `DEEPSEEK_API_KEY`，并按需设置模型名称及接口地址。发布前运行 `npm ci` 和 `node cloud/build.mjs`，使用 `cloud/schema.sql` 初始化或增量更新 D1 表，再通过 Wrangler 发布。

本地文件型存储的会话和任务写入在单个服务进程内串行化并使用临时文件替换；发现记录格式损坏时停止写入，保留原文件供排查。该保护不等于跨进程并发控制。知识卡的版本键为不可变记录；并发写入冲突时返回错误，不覆盖已有版本。

## 验证与边界

运行 `npm test` 执行状态机、模型接口模拟、任务校验、教师摘要和HTTP集成测试。HTTP测试需要本机端口监听权限。模型模拟测试说明程序在指定输入下的行为，不代表真实模型质量或教学效果；真实模型对照和教师试用仍需另行完成。

`POST /api/session` 需要 `username`（1–32 个字符）。用户名由学生填写，无需密码，建议使用昵称。教师口令保护的看板可以按用户名筛选学习记录。学生接口不会返回记录中的用户名。

当前程序支持题图与作答图片进入配置的模型接口，实际识图能力取决于所配置模型。

浏览器图片边界测试位于`tests/browser-image.mjs`，需自行安装Playwright并用`PLAYWRIGHT_MODULE_PATH`指定模块目录，然后运行`node tests/browser-image.mjs`。该脚本使用临时服务与模拟API，不使用模型密钥、不修改现有学习记录；移动视口测试不能代替安卓真机相机与移动网络验证。

手机两页的浏览器回归位于`tests/browser-mobile.mjs`，使用相同的Playwright配置。覆盖题目与作答页切换、浏览器触摸输入、纵向滚动边界、隐藏页焦点、结果标签及草稿保留。教师页面路由和认证另有HTTP、Worker测试：页面可打开不代表学习记录免认证。
